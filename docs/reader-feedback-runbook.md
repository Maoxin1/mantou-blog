# 评论讨论清单自动同步候选（2026-10-07）

首版评论已完成授权发布和生产只读验收。本节描述新的自动同步候选，仍需按精确源码范围批准发布；下面的初始化、注册、点赞和邮件方案仅是历史记录。数据库和现有管理员继续复用。

生产构建显式使用 `hugo --config hugo.toml,config/comments-production.toml`，指向 `https://mantou-comments.vercel.app`；默认 `hugo.toml` 仍保留关闭评论的配置，便于测试和回退。部署工作流的候选改动启用该覆盖配置，合并主分支将触发正式站点发布，因此必须另行批准。

- 按需加载，免注册，昵称必填、邮箱选填，留言及回复审核后公开。
- 中英文共享中文规范路径；首版不开放文章或留言点赞，不写计数器，不发送邮件通知。
- `reactions=false` 同时关闭反应请求及按钮；旧反应测试继续使用其独立合成配置。
- 正式博客构建后，`scripts/discussion_manifest.py` 从实际输出页面生成并校验 `/feedback/threads.json`。它只包含已发布文章和作品；草稿、旧地址重定向、普通页面及未启用评论的预览不进入清单，中英文共用规范路径。仅英文页面也使用不带 `/en` 的规范讨论标识。
- 清单记录精确源码提交，与同一生产发布的 `/version.json` 对应。后端仅从固定正式博客地址读取这两份公开文件，拒绝重定向和任何版本、格式或路径不符的清单。新内容随通常的博客生产发布纳入讨论，无需逐次重新部署后端。
- 后端每个实例按需使用 60 秒短缓存，并发请求共享刷新。实例重启后重新获取，缓存用于性能而非长期存储。读取失败时保留最近验证的集合或部署内的 209 项回退清单，尚未同步的新页面暂不可评论。有效新清单替换旧集合；下架路径在刷新后关闭，但数据库中的评论保留。
- `x-discussion-registry-version` 响应头给出已验证的公开源码提交，或 `fallback`，用于只读核验同步是否真正成功。清单刷新日志仅包含结果、公开提交、数量和有限错误类别。
- 管理员只在受保护的后端生成主机登录，到期关闭；公开读者接口不随临时管理员截止时间关闭。
- 公开启用前需核验真实 CORS、正式域名、Cloudflare Pages 构建提交和无注册访客流程；本地浏览器测试不替代这些检查。

以下是保留的历史设计记录，不能直接当作本轮操作指令。

# 图片与读者反馈

首页照片只引用 `data/home.yaml` 中指定的已公开文章及原图，配文由中英文 i18n 维护。
Hugo 从现有图片生成 WebP 响应式预览。文章归档只为正文已有本地图片的文章显示缩略图，
不补造图片或为纯文字文章放置占位图。原文与原图保持不变。

每篇文章和作品的文末都有反馈入口，邮件主题与正文自动带上当前文章和规范地址。
这只是邮件入口，不代表已实现公开评论或点赞。

## 评论与点赞接入

前端使用官方 `@waline/client@3.15.2`，随站点托管，附 MIT 许可证。
`hugo.toml` 的 `[params.feedback].serverURL` 留空时，公开页面不展示评论表单、
点赞按钮或计数，也不会加载 Waline。填写并发布经过验证的 HTTPS 服务地址后启用。

设计约定：

- 读者主动打开后才加载评论，失败时可重试，邮件入口始终保留。
- 无需注册；昵称必填，邮箱选填；不提供图片上传、表情搜索或浏览计数。
- 只保留“有帮助”一种文章反应，计数来自服务端，不制造本地虚假总数。
- 中文和英文版使用中文规范地址关联同一条讨论；老地址通过现有重定向进入规范地址。
- 浅深色跟随博客；公开留言需要审核。正文搜索不索引评论或反馈入口。

## 服务端部署与启用条件

官方当前路线为 Vercel + Neon Postgres：
https://waline.js.org/en/guide/get-started/

1. 在站点所有者的 Vercel 和 Neon 账户部署官方 Waline 服务，并保存数据库配置到服务环境变量。
2. 初始化数据库，完成所有者管理员注册；首个注册者会获得管理员权限，因此在开放给读者前完成。
3. 设置 `SITE_NAME`、`SITE_URL=https://mantou-blog.pages.dev`、
   `SECURE_DOMAINS=mantou-blog.pages.dev`、`COMMENT_AUDIT=true`、`IPQPS=60`、
   `DISABLE_REGION=true`、`DISABLE_USERAGENT=true`；关闭公开注册，保留匿名评论。
4. 确认账户套餐、配额与到额行为，不在未明确授权时开通付费方案。
5. 实测昵称留言→待审核→管理员批准→刷新可见；验证回复、删除和垃圾评论管理。
6. 实测点赞成功后刷新保留，并在第二个浏览器看到同一服务端总数；确认重复点击行为。
7. 验证手机、英文页、深色模式、服务故障以及邮件备用入口。
8. 通过 PR 填入真实 `serverURL`，正常验证、合并和部署。连接插件本身不代表服务已部署。

服务和数据库的登录凭据不得写进仓库。访客昵称、邮箱和留言交由服务存储；应在启用时
再次核对公开说明、保存期限和管理员访问范围。

目前 `serverURL` 为空：图片和邮件入口可独立发布，公开点赞、评论仍待服务部署。
