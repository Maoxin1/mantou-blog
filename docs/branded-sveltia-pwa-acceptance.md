# 品牌化 Sveltia PWA 验收

> 先证明它缩短了自己的发布链路，再考虑把它当作可公开的方法或产品案例。

## 功能与用户承诺

- 功能：把 Sveltia 灰度后台安装为带 mantou 名称与图标的桌面 PWA；
- 真实使用者：博客维护者本人；
- 它要帮助用户完成：点击桌面图标进入内容工作台，创建、保存和发布阶段作品；
- 可公开主张：这是可安装、独立窗口运行的品牌化网页应用；
- 非目标：不是原生客户端，不承诺断网编辑、跨设备草稿同步或绕过 GitHub 审核流程。

## 验收标准

- 正常路径：在线打开`/admin/sveltia/`，安装后显示`mantou 内容工作台`和 mantou 图标，从桌面启动后进入同一后台；
- 最小可接受结果：浏览器判定应用可安装，名称、图标、启动地址和独立窗口模式正确；
- 明确失败条件：仍显示 Sveltia 默认品牌、安装后打开错误地址、浏览器报告不可安装，或品牌配置破坏登录与内容工作流；
- 发布条件：自动检查通过、正式站清单检查通过，并在 Windows 上完成一次真实安装和启动验收。

## 边界状态

- 旧安装可能保留旧名称或图标，需要卸载后重新安装；
- GitHub 登录过期时应回到正常登录流程，不能绕过权限；
- 后台资源继续使用`no-store`并绕过博客 Service Worker，防止旧配置污染发布；
- CDN、GitHub 或 OAuth 不可用时允许明确失败，并保留`/admin/`稳定后台作为回退入口；
- 离线编辑和发布不在本轮承诺中。

## 证据分层

- 单元/静态检查：品牌字段、图标文件、共享配置和最小差异规则；
- 浏览器验收：动态 Manifest 的名称、图标、启动地址、`standalone`模式和 Chromium 可安装性；
- 部署后检查：正式地址的标题、Manifest 与可安装性；
- 人工或真实设备验收：Windows 桌面图标、无地址栏启动、登录状态和进入编辑器；
- 线上反馈与监测：首次真实作品发布后复核完整发布链路。

## 未覆盖风险

- 当前明确不测：断网编辑、多个桌面系统、浏览器长期升级后的全部差异；
- 原因：Sveltia 当前不支持离线，且首要使用环境是 Windows Chromium；
- 重新评估触发条件：Sveltia 或浏览器升级、主力设备变化、真实安装失败或出现离线刚需。

## 复盘

- 实际结果：品牌配置已部署；正式站标题、动态Manifest、可安装性与后台缓存边界已通过自动验收，仍等待真实桌面安装；
- 反证或失败：实现前测试确认默认品牌仍为`Sveltia CMS`；
- 测试曾遗漏什么：过去验证了移动端内容工作流，但未验证桌面安装身份；
- 下一步继续、调整或停止：通过真实安装后继续用下一项真实作品验收发布，不提前替换`/admin/`稳定入口。
