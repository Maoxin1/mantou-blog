# 边缘风险登记表

这份登记表记录“当前证据能证明什么”和“仍然不能证明什么”。它不是测试数量清单；只有会影响发布、隐私、用户任务或品牌可信度的失败才进入高优先级。

状态定义：

- `阻断`：每次提交必须通过，否则不得发布；
- `线上`：部署后或定时检查，不因外部短暂波动阻塞普通内容提交；
- `人工`：依赖语境、真实设备或判断，自动化只能辅助；
- `观察`：当前投入产出比不高，达到触发条件后再升级。

## 使用规则

1. 新功能开始前，复制[功能验收模板](feature-acceptance-template.md)，先写主张、失败模式和非目标。
2. P0必须有阻断性证据；无法自动判断的P0必须增加人工发布门禁。
3. 外部服务与正式环境使用独立线上检查，不放进每次PR的快速测试。
4. 测试失败后先判断是产品缺陷、测试定义错误还是外部波动，不为全绿降低标准。
5. 每次真实失败都要回到本表：补充失败模式、证据和重新评估条件。

- 重新启用Worker Git Builds前，必须先在仓库增加明确的Wrangler配置、用途说明和独立验收，避免同一提交产生互相矛盾的部署状态。
