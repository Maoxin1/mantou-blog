# 基础访问统计不变量

功能 `ANL`；文档 `INV-DOC-ANL-001`；2026-10-08。关联[功能规范](analytics-v1.md)、[边缘缺口](analytics-edge-case-gaps.md)、[台账](../feature-ledger.md)与[参考研究](../research/analytics-20261008/README.md)。

不变量是给定前提下必须持续成立的性质，既可用于产品行为，也可用于结果解释与验收证据。它不是“任意服务异常下全部数据永远正确”。下表区分已采纳范围的必然约束与尚待确认的候选约束；候选不得直接成为发布门禁。本阶段未新增或执行属性、模糊或状态机测试。

## 明确不作为不变量的说法

- “刷新同页 PV 不变”“同一个真人在多个设备只有一次访问”：与 PV 及本轮不做 UV 的范围不符。
- “一条采集请求对应一个 PV”“收到 2xx 就已持久化”“脚本恢复后补回全部漏计”：缺少服务商端证据或能力。
- “数字永远单调增长”“所有页面行相加恒等于总数”“PV 永远大于等于 Visits”“不同查询与设备得到完全相同数值”：采样、区间、迟到更新、表格截断和口径会改变前提，不适合作为无条件发布断言。
- “所有异常环境都能正常阅读”：资源耗尽、正文自己的依赖失败或浏览器崩溃不属于单独统计故障隔离的前提。
- “统计历史支持无限期恢复”“必须有跨进程事务和本地部分写入恢复”：本站不拥有统计存储，这些会扩展范围。

属性/模糊/状态机适用不代表立即需要实现测试框架。优先复用现有 E2E 和研究观测；只有采纳相应候选行为并出现组合覆盖价值时，才补最小测试模型。供应商报表与权限仍需真实只读验收。
